# ZENAIM KEYBOARD ハードウェアノート

*Unofficial hardware notes on the ZENAIM KEYBOARD — MCU, peripheral buses, key-scan engine and firmware recovery.*

> **非公式ディスクレーマ** — 本ドキュメントは非公式であり、キーボードの製造元および関連会社とは無関係です。製品名・商標は各権利者に帰属し、記述目的でのみ使用しています。内容はファームウェアの静的解析とデバイスの観測から独自に作成したもので、正確性・完全性は保証されません。

対象: ファームウェア 1.2.5 の観測時点 (2026-10)。確度の表記: 断定できないものは「(推定)」、実機で確認できていないものは「未確認」と記す。

## 1. MCU とメモリ

- MCU: **STM32G473 系 (STM32G4 ファミリ、Cortex-M4F、170 MHz、FPU 搭載)** と推定。
  - 根拠: ファームウェアが使う周辺レジスタの構成が STM32G4 系のレジスタマップと整合する (推定)。正確な型番は未確定 (§6)。
- 内蔵フラッシュ: **512 KiB**、ページ 2 KiB。ROM ブートローダー (ROM DFU) の表示から確認。
- 内蔵 SRAM: **128 KiB**。
- ファームウェア配置: フラッシュ先頭 64 KiB (0x08000000–0x0800FFFF) は UF2 ブートローダー領域で、通常のファームウェア UF2 には含まれない。アプリは **0x08010000** から約 106 KiB。
- USB: **フルスピード device のみ** (High Speed 非対応)。アプリ側の HID 構成は 4 インターフェース、エンドポイントは 32 byte / 1 ms (詳細は [protocol.md §1.2](protocol.md))。

## 2. 周辺バス

| 機能 | バス / ピン | 確度 |
|---|---|---|
| RGB LED ドライバ | I2C2 (PA8 = SDA / PA9 = SCL) | 推定強 (LED 制御系統からこのピン初期化が呼ばれる) |
| 設定ストレージ | 外付け SPI NOR フラッシュ。SPI4 (SCK = PE2 / MISO = PE5 / MOSI = PE6 / CS = PE3) | 接続は確定。型番は未同定 |
| デバッグ (ログ出力) | USART1 (PA2 / PA3)、115200 bps | 推定 |
| キー / 温度センサー | ADC2 / ADC3 / ADC4 (行ピン 6 本は §4) | 確定 (走査系の解析による) |

- 設定ストレージは **3 バンクの冗長コピー**を持ち、起動時に多数決で復旧する設計と推定 (ファームウェア内のエラーメッセージ群から)。セクター単位の消去・書込を行う。
- 設定・校正データはこの外付けフラッシュ側にあり、ファームウェア本体とは独立している。ファームウェア更新で設定が保持されることを観測済み。
- LED ドライバ IC の型番・個数、外付けフラッシュの型番は未確定 (§6)。

## 3. ボタンと復旧

ケース上面 (MEM2 / MEM3 キーの奥側) の 2 つの穴からボタンを押せる。

| ボタン | 位置 | 挙動 |
|---|---|---|
| RUN | MEM3 キー奥側 | 短押し = リセット。**素早く 2 回 = UF2 ブートローダー** (ZENAIM ドライブが出現) |
| BOOT | MEM2 キー奥側 | **押しながら USB 接続 = STM32 ROM DFU** (0483:df11 "DFU in FS Mode") |

復旧手順 (優先順):

1. **UF2 再コピー**: RUN を素早く 2 回 → ドライブ出現 → ドライブに `firmware.uf2` をコピー → 自動書込・再起動。
2. **ROM DFU**: BOOT を押しながら USB 接続 → 以下のコマンドでアプリ領域を再書込。

   ```sh
   dfu-util -d 0483:df11 -a 0 -s 0x08010000:leave -D <app.bin>
   ```

   書込対象はアプリ領域のみで、ブートローダー領域には触れない。
3. (上級) **SWD**: PA13 / PA14 のデバッグポートから OpenOCD / pyOCD などで読み書きする。ブートローダーを含む全領域を読める唯一の経路 (推定)。

補足:

- UF2 ブートローダーのドライブは FAT、ラベル `ZENAIM`、32.1 MiB、パーティションなし (superfloppy)。`firmware.uf2` の名前でコピーされたファイルが書き込みトリガーになる。
- コピーしてもすぐ発火しないことがある。`sync` とアンマウントで書き戻しを確定させてから数十秒待つ。書込中はケーブルを抜かない。
- **既知の事象**: ファームウェア書き込み直後の温リセット初回起動で、左半分の LED が消灯したままになることがある (1 例)。USB を抜き挿しすると正常化する。書き込み後の確認は冷起動 (抜き挿し後) で行うのが安全。

## 4. キー走査エンジン

ホール素子を **6 行 × 18 列 = 108 キー + 温度 6ch** のマトリクスとして走査する。キー索引 = 行 × 18 + 列。

行ピン (6 本、アクティブ Low):

| 行 | ピン |
|---|---|
| 0–5 | PA15 / PC10 / PC11 / PC12 / PD0 / PD1 |

列 (ADC 入力、18ch を 3 つの ADC で分担):

| ADC | チャネル数 | ピン |
|---|---|---|
| ADC2 | 7 | PA4 / PA5 / PA6 / PA7 / PC4 / PC5 / PB2 |
| ADC3 | 9 | PB0 / PB1 / PE7 / PE8 / PE9 / PE10 / PE11 / PE12 / PE13 |
| ADC4 | 2 | PE14 / PE15 |

温度 6ch (ADC4): PB14 / PB15 / PD8 / PD9 / PD10 / PD11。

1 行分の走査:

1. 行ピンを選択する (アクティブ Low)。
2. 約 **17 µs** 待つ (整定待ち)。
3. ADC2 / ADC3 / ADC4 を同時に変換開始する (DMA・連続変換。ソフトウェアは完了を待って回収)。
4. 回収した 18 値に **4 サンプルの平滑化**を適用して保持する。

1 行分の値の並び (バッファ順) は **[ADC2×6][ADC3×2][ADC2×1][ADC3×7][ADC4×2]** で、PCB 配線順に列 0..17 へ対応する。

温度は生 ADC 値のまま返し、摂氏への換算はホスト側で行う。換算式・パラメータ (サーミスタ想定 NCP15WF104F03RC 相当など) は [protocol.md §3.13](protocol.md) を参照。ADC 参照電圧は機種・リビジョンで異なる (同 §5)。

確度: 走査の構造 (行ピン・チャネル列・並び順・平滑化) はファームウェアの静的解析で確認した。走査周期そのものの実測はしていない (数百 Hz 級と推定)。

## 5. UF2 / ファームウェア書き込み

- UF2 のファミリ ID は **`0x4c71240a`**。microsoft/uf2 の family 一覧に "STM32G4" として登録されている汎用 ID で、ベンダー独自のものではない。
- 書き込みは、UF2 ブートローダーのドライブに `firmware.uf2` の名前でコピーするだけ (§3)。UF2 は 512 byte ブロックで、書込先はアプリ領域 (0x08010000 以降) のみ。
- **署名・ハッシュの検証は観測されていない** (ファミリ ID の照合のみで受理された)。書き込みは自己責任で行い、事前に §3 の復旧手順を確認しておくこと。
- 注意: ハードウェアリビジョン (bcdDevice) はファームウェアに埋め込まれているため、誤ったリビジョン用の UF2 を書き込むとデバイスが誤った bcdDevice を名乗る。対象機種・リビジョンに合った UF2 を使うこと (対応表は [protocol.md §5](protocol.md))。
